# Comprehensive Data Inventory — Between Us

**Tagline**: Two People. One Private Connection.  
**System Phase**: Phase 03 — Privacy & Data Classification  
**Status**: Authoritative Privacy Specification  

---

## 1. Executive Summary

This document serves as the master data inventory for **Between Us**. Every piece of data created, processed, transmitted, or cached across all system layers (Client Browser, Signaling Server, coturn TURN Relay, Vercel Edge, Cloudflare) is cataloged and assigned an explicit purpose and scope.

---

## 2. Categorized Data Inventory

### Category A: Audio Data
* **A.1 Microphone Stream**: Raw audio PCM stream captured via browser `getUserMedia({ audio: true })`. Resides strictly in local browser process memory.
* **A.2 Encrypted Audio Packets**: Real-time Opus encoded audio frames encrypted via DTLS-SRTP (AES-GCM). Transmitted direct P2P or via coturn relay.
* **A.3 Audio Web Buffers**: Ephemeral 10-20ms Web Audio hardware playback buffers in volatile browser RAM.
* **A.4 Audio Processing State**: Local mute toggle status, echo cancellation state, gain control parameters.

### Category B: Video Data
* **B.1 Camera Stream**: Raw video frame stream captured via browser `getUserMedia({ video: true })`. Resides strictly in local browser process memory.
* **B.2 Encrypted Video Packets**: Real-time VP8/AV1 encoded video frames encrypted via DTLS-SRTP (AES-GCM). Transmitted direct P2P or via coturn relay.
* **B.3 Video Frame Buffers**: Ephemeral video rendering buffers in GPU/volatile browser RAM during active playback.
* **B.4 Video Processing State**: Camera facing mode (`user` / `environment`), local video enable/disable toggle status.

### Category C: Device Identity
* **C.1 Device Identity Private Key**: Local **Ed25519** private cryptographic key generated via Web Crypto API (`extractable: false`). Saved in IndexedDB.
* **C.2 Device Identity Public Key**: Base64 SPKI string of the public identity key shared during peer pairing.
* **C.3 Public Identity Fingerprint**: SHA-256 hash of the public identity key used as a 64-character hex identifier.
* **C.4 Identity Status**: Paired vs unpaired state flag stored in local IndexedDB.

### Category D: Pairing Data
* **D.1 Ephemeral Pairing Code**: Cryptographically random 6-digit numeric token generated by signaling server with a 3-minute TTL.
* **D.2 Ephemeral Pairing Token**: Single-use UUID token associated with a pairing session in signaling RAM.
* **D.3 Pairing Session State**: Temporary state machine tracking pairing handshake progress (`REQUESTED`, `SUBMITTED`, `VERIFIED`, `EXPIRED`).
* **D.4 Expiration Timestamps**: Unix timestamp marking pairing code expiration.

### Category E: Safety Verification
* **E.1 SAS Safety Fingerprint**: Short Authentication String derived via $\text{HKDF-SHA256}(PubKey_{\text{min}} \parallel PubKey_{\text{max}})$, displayed as an 8-character hex string (e.g. `A4B8 - 91F2`).
* **E.2 SAS Verification Status**: Local boolean flag indicating whether the user has manually verified and approved the partner's SAS string.
* **E.3 Identity Change Alert State**: System alert state triggered when an unrecognized public identity key is presented by a paired peer.

### Category F: WebRTC Data
* **F.1 SDP Offer**: Session Description Protocol string containing media capabilities, DTLS fingerprints, and SRTP cipher suites sent by initiator.
* **F.2 SDP Answer**: SDP string containing accepted media parameters and responder DTLS fingerprint.
* **F.3 ICE Candidates**: Transport addresses (host, srflx, relay IPs and ports) trickled via signaling.
* **F.4 Connection State**: Ephemeral status (`new`, `connecting`, `connected`, `disconnected`, `failed`, `closed`).
* **F.5 DTLS Master Keys**: Ephemeral SRTP master keys negotiated inside browser C++ WebRTC core.
* **F.6 STUN / TURN Configuration**: Hardcoded STUN/TURN server URLs and ephemeral REST API credentials.

### Category G: Session Data
* **G.1 Ephemeral Session Identifier**: Random UUID identifying an active WebSocket signaling transaction.
* **G.2 Call State**: Volatile UI state (`IDLE`, `INITIATING`, `INCOMING`, `CONNECTING`, `CONNECTED`, `ENDING`).
* **G.3 TURN REST Token**: Short-lived HMAC-SHA-1 credential generated by signaling server (15-minute TTL).

### Category H: Network Metadata
* **H.1 Source / Destination IP Addresses**: Public IP socket headers processed by Cloudflare, Vercel, Signaling VPS, and coturn VPS.
* **H.2 Connection Timestamps**: Timestamps of socket establishment and disconnection.
* **H.3 Connection Duration**: Active socket lifespan calculated at host network interface.
* **H.4 Packet Volume & Throughput**: Aggregate byte and packet counters processed by network interfaces.

### Category I: Browser Data
* **I.1 IndexedDB Storage**: Origin store `BetweenUs_Security_Store` holding non-extractable identity key and partner public key.
* **I.2 Cache Storage**: Service Worker cache `BetweenUs_AppShell_v1` holding static frontend files.
* **I.3 Browser Permissions**: Permission state for `camera` and `microphone`.
* **I.4 Volatile RAM**: Process memory allocated to active DOM, Web Crypto, and WebRTC objects.

### Category J: Application State
* **J.1 Current UI View**: Active screen (Home, Pairing Modal, Active Call Screen, Alert Screen).
* **J.2 Local Audio/Video Toggles**: User UI button states (Mute Audio, Video Off).
* **J.3 Local Error State**: Transient localized error message string displayed in UI.

### Category K: Log Data
* **K.1 Client Console Logs**: Non-sensitive operational messages in local browser Developer Tools console.
* **K.2 Signaling Server Stdout**: High-level lifecycle event logs printed to signaling VPS stdout.
* **K.3 Coturn Daemon Logs**: Minimal relay daemon connection/disconnection logs.
* **K.4 Cloudflare Edge Logs**: Infrastructure edge HTTP access logs retained per Cloudflare policy.

### Category L: Security Data
* **L.1 Rate-Limit Counters**: Sliding window attempt counters for pairing submissions and WebSocket frame rates.
* **L.2 Anti-Replay Nonce Cache**: Server RAM sliding cache of received nonces (60-second window).
* **L.3 IP Drop Tables**: Firewall drop lists for IPs violating rate limits.
